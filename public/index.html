        Git requirements & setup
        
Checking Git availability…

        
    
          
  • Git 2.31 or newer must be available to Argus. Finish any macOS developer-tools installation or licence prompts in Terminal first.
    • 
          
  • Local folders must be Git checkouts with an initial commit. Empty or broken repositories are skipped; other selected repositories can still be added.
    • 
          
  • For cloning, use the actual clone URL and an existing writable destination with enough free space. Do not paste git clone, passwords or tokens.
    • 
          
  • Private HTTPS repositories need saved Git credentials. SSH needs an authorized key available to your agent, a verified host key, and network/VPN access. Complete sign-in in Terminal first: cloning cannot prompt for credentials.
    • 
          
  • Git remote API sign-in is separate from Git authentication. Submodules, Git LFS, project SDKs, package-registry access and environment values may require separate setup.

YOUR ACTION CONTROLS IT
When data can leave this Mac
Never silently

          

            
Coding CLI requests
Your prompt, private AI-kit instructions, selected attachments, and—only when enabled—the saved messages in this chat are sent to the coding-agent CLI you choose. Argus does not support hosted answer-provider APIs or copy CLI credentials.

            
Git remotes
Repository data reaches the configured Git remote only when you fetch, pull, push, or run an AI-approved Git action.

            
API Client
URLs, headers, query values, and bodies are sent only to the destination shown in the request when you press Send.

            
Permission-aware backup
Private workspace data is encrypted locally. Drive receives no source code unless the same save first completes a successful Git remote push.

          

        

        
◌
Not persisted by Argus
Live service logs, terminal output, current API responses, running process state, and transient agent-job output remain in memory and disappear when their session ends. Connected source repositories stay in their original folders—Argus stores references to them, not copies.

        

          
Connected repository locations0

        

        

          
Deletion, uninstall, and remote-copy behaviorImportant

            
Offboarding a repositorydisconnects it from active tabs and Services and stops its running work. All saved data stays on disk: Nexus and repository chats, session references, chat memories, attachments, private AI kits, API collections, environments and settings. The source repository and its Git work remain untouched. Reconnect the same folder to use its saved setup again.

            
Deleting an API request or folderremoves that item from Argus's local API collection files. Deleting a parent removes its saved children too.

            
Uninstalling Argusdoes not automatically erase Application Support data, API collections in Documents, the backup working copy, or Keychain entries. Remove those locations explicitly if you want a complete local wipe.

            
Git remote and Google Drive backupscontain only the latest snapshot. Every save atomically replaces Drive and force-updates the dedicated Git remote main branch to one latest commit; provider-side audit or garbage-collection records can remain outside Argus's control.

          

        

      

      
Fresh reset: erases every Argus-managed local record, connected-repository reference, chat memory/model, AI kit, API collection, Keychain secret, and configured backup copy. Your Git repositories and CLI-owned login remain untouched.
